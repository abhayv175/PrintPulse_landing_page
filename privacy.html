Section 1

Vendor Google OAuth Data Handling & Limited Use Disclosure

PrintPulse enables print shop owners and kiosk operators (“Vendors”) to authenticate their administrator accounts seamlessly via Google Sign-In. When a vendor signs in with Google, PrintPulse requests and receives only basic profile metadata provided through Google's standard OpenID Connect authorization flow:

Data Field OAuth Scope Specific Operational Purpose
Full Name profile To address the print shop operator in the vendor dashboard and on printed receipts.
Email Address email To uniquely identify the vendor account and send critical administrative notifications.
Google User Identifier openid / sub To authenticate sessions and isolate multi-tenant shop queues (/shop/{vendor_id}).
Google API Services User Data Policy Compliance:

PrintPulse's use and transfer of information received from Google APIs to any other app will adhere to the Google API Services User Data Policy, including the Limited Use requirements.

  • Strict No-Sale Guarantee: PrintPulse never sells, rents, licenses, or trades Google user profile data to any third parties, brokers, or marketing networks.
  • No Advertising Use: PrintPulse does not transfer or use Google user data for serving advertisements, personalized retargeting, or behavioral surveillance.
  • No AI Model Training: Google user data is never used to train generalized artificial intelligence or machine learning models.
Section 2

Customer Document Uploads & Automated Deletion

PrintPulse operates a touchless, browser-based customer web portal hosted at /shop/{vendor_id}. Customers upload PDF documents and printable imagery directly from their mobile phones or laptops without creating an account or downloading an app.

1 TLS 1.3 Ingestion

Documents are transmitted exclusively over encrypted HTTPS (POST /api/documents/batch-upload) directly into isolated per-vendor storage staging buffers.

2 Automated Analysis

The backend performs automated page counting, page-range extraction, and color-mode validation strictly to compute precise print pricing and generate hardware printer spool files.

3 Immediate Deletion

Upon print job completion, order cancellation, or 24-hour expiration, the file is automatically and permanently purged from server disk storage (os.unlink).

Zero Long-Term Retention Policy:

PrintPulse does not retain archives, backups, or shadow copies of customer documents. Files are strictly treated as volatile, ephemeral print streams. Once marked as printed or cancelled, the underlying files are permanently wiped from the operating system's filesystem. Customer contents are never parsed for telemetry, content marketing, or advertising.

Section 3

Payment & NPCI UPI Verification Data

PrintPulse empowers print shops with direct, peer-to-peer (P2P) payments using India’s National Payments Corporation of India (NPCI) Unified Payments Interface (UPI) standard:

  • Direct Peer-to-Peer Settlement: Customers transfer funds directly into the vendor’s verified merchant UPI Virtual Payment Address (VPA). PrintPulse acts solely as a technical signaling bridge and never holds customer funds in escrow.
  • Transaction Reference Number (UTR) Storage Only: When a customer completes a UPI payment, they submit the 12-digit bank Unique Transaction Reference (UTR) number through the web portal. PrintPulse logs this UTR solely to associate the payment with the active print order.
  • Zero Collection of Financial Credentials: PrintPulse never collects, requests, processes, or stores bank account passwords, debit/credit card numbers, CVVs, or UPI PINs. All credential entry occurs exclusively within the customer’s trusted UPI client (such as Google Pay, PhonePe, Paytm, or BHIM).
Section 4

PrintPulse Android Vendor App & Local Device Storage

Print shop vendors utilize the PrintPulse Android App to monitor the incoming print queue and control printer spooling. The application utilizes local device storage strictly within standard operating system sandboxes:

Android SharedPreferences Scope:

The application stores only lightweight session tokens and configuration preferences locally:

  • Authentication JWT / Session Token: Preserved locally to maintain encrypted WebSocket channels (/ws/vendor/{vendor_id}) without requiring re-authentication upon app relaunch.
  • Kiosk Profile Preferences: Local pricing rules (Black & White vs Color rates) and active theme settings.

No customer PDFs, personally identifiable customer records, or financial information are ever permanently persisted on the vendor’s Android device.

Section 5

Multi-Tenant Architecture & Shop Isolation

PrintPulse serves multiple independent print shops across colleges, universities, and commercial printing centers through a strictly isolated multi-tenant design:

  • Isolated Shop Queues: Every print job is bound strictly to a validated vendor_id. Shop A cannot inspect, intercept, or modify jobs submitted to Shop B.
  • Filesystem Directory Sandboxing: Staged files are isolated into shop-specific directories (uploads/{vendor_id}/{order_id}/) preventing directory traversal or cross-tenant leaks.
  • WebSocket Realm Partitioning: Live printer notifications and customer payment updates broadcast strictly within isolated per-vendor and per-order channels.
Section 6

Transport Security & Infrastructure Safeguards

PrintPulse enforces rigorous technical and operational controls to protect data in transit and at rest:

Strict HTTPS / TLS 1.3

All API traffic, file uploads, and web socket handshakes are encrypted end-to-end.

Local UDP Discovery

Kiosk auto-discovery packets run strictly on local private subnets and never broadcast externally.

Section 7

User Rights, Data Erasure & Control

We uphold transparent user control over stored information:

  • Vendor History Purge: Vendors can trigger an immediate deletion of their historical print orders via the in-app “Clear Order History” option or via DELETE /api/vendor/{vendor_id}/history.
  • Customer Data Rights: Because customer documents are purged immediately upon print completion, no persistent personal archives exist. Customers may request status inquiries at any time.
  • Account Deletion: Vendors can revoke Google OAuth access at any time via Google Account Permissions.
Section 8

Children’s Privacy

PrintPulse does not knowingly collect personally identifiable information from children under the age of 13 (or under 16 in applicable jurisdictions). If we become aware that personal information of a child has been collected without parental consent, we take immediate action to delete that information permanently.
